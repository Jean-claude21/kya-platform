# Signature design system integration

## Scope

Promote the user-approved `kya-signature` HTML/CSS design into the React application.
Preserve authentication, OAuth consent, API calls and existing workbenches. Keep the
five employee destinations and a separate administration entry. Do not deploy, publish
an artifact, change permissions or claim that illustrative records are live.

## Acceptance

- Near-white KYA canvas, official intact logo, self-hosted Inter, square controls,
  solar home banner and flat capability/action layout match the approved prototype.
- Home, catalogue, connections, spaces, Studio and administration remain reachable;
  authentication and consent inherit the same tokens without changing their behavior.
- Keyboard navigation, responsive scrolling, search and errors are checked.
- The portable design skill contains the canonical eight-section DESIGN.md, tokens,
  official logo, licensed font, useful reference and a runnable integrity validator.
- Studio displays the actual packaged skill files, not invented file contents or checks.
- Unconnected functionality and sample data remain visibly identified.

## Boundaries

This is a local implementation increment. Real catalogue installation, entity/unit
authorization discovery, publication and a personal approval inbox require separate
API integration work. A selectable preview context never grants permissions.
