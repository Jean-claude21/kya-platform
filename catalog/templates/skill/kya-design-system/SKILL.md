# KYA Design System

Create clear, role-aware KYA experiences with the official visual language.

Read [references/DESIGN.md](references/DESIGN.md) before producing visual or interface work. Read
[references/implementation.md](references/implementation.md) when writing frontend code.

Use the official KYA-Energy Group logo from
[`assets/brand/kya-energy-group-logo.png`](assets/brand/kya-energy-group-logo.png) whenever the
requested output requires the Group logo. Copy the asset into the output; do not redraw, recolor,
crop, stretch, trace, or synthesize it.

## Required behavior

1. Write the product name exactly as `KYA-Platform`.
2. Use the packaged official logo and palette; preserve the semantic role of each accent.
3. Keep organizational context, provenance, version, access, and state visible when relevant.
4. Prefer lists, trees, timelines, tables, and split views when they explain relationships better
   than generic cards.
5. Label examples and unconnected functions explicitly; never invent operational evidence.
6. Check keyboard access, focus visibility, responsive layouts, reduced motion, contrast, loading,
   empty, error, and restricted states.
7. Keep AI responsible for reasoning and governed software responsible for deterministic execution.

Do not publish, deploy, approve, or replace a production theme unless the user explicitly requests
that external action. Return implementation-ready work for review through the KYA-Platform
publication workflow.
